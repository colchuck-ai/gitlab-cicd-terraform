# gitlab-cicd-terraform

The purpose of this [gitlab cicd component](https://docs.gitlab.com/ci/components/) project is to publish components that can be used to construct opinionated terraform cicd pipelines.

It should be used in conjunction with:

- [gitlab-cicd-deployment-workflow components](https://gitlab.example.com/engineering/dev-tools/internal/gitlab-cicd-deployment-workflow)
- [gitlab-cicd-release-workflow components](https://gitlab.example.com/engineering/dev-tools/internal/gitlab-cicd-release-workflow).
- [gitlab-cicd-temp-creds components](https://gitlab.example.com/engineering/dev-tools/internal/gitlab-cicd-temp-creds)

See [usage](#usage) for examples.

## Components

### `plan-and-apply` Component

This component assumes that your repository follows the [standard terraform deployment structure](https://gitlab.example.com/engineering/workload-handbook/internal/workload-handbook/-/blob/master/tools/terraform/terraform.md) or the [standard terraform module structure](https://gitlab.example.com/engineering/workload-handbook/internal/workload-handbook/-/blob/master/tools/terraform/terraform.md).

The `plan-and-apply` component creates hidden jobs based on the inputs provided:

- `.plan:<environment>:<provider>:<region>`: Navigates to `environments/<environment>/<provider>/<region>`
- `.apply:<environment>:<provider>:<region>`: Applies changes in the same directory

All jobs run `terraform init`, create plan files (`plan.tfplan`, `plan.json`, `plan.report.json`), and handle apply logic based on the `use-plan` setting. Artifacts expire after 30 minutes by default.

### `plan-and-apply` Component Inputs

| Name          | Type      | Description                                                                                | Required | Default |
| ------------- | --------- | ------------------------------------------------------------------------------------------ | -------- | ------- |
| `environment` | `string`  | `prod`, `test`, etc.                                                                       | yes      |         |
| `provider`    | `string`  | `aws`, `vault`, etc.                                                                       | yes      |         |
| `region`      | `string`  | `global`, `us-east-1`, etc.                                                                | yes      |         |
| `use-plan`    | `boolean` | If true, the apply job expects a saved plan; if false, it applies directly with a warning. | no       | `true`  |

### `plan-policy-check` Component

The `plan-policy-check` component creates a hidden job that runs OPA (Open Policy Agent) policy checks against Terraform plans. It evaluates the plan.json file generated by the plan job against policies defined in a .opa/ directory at the root of your project.

The component creates a hidden job with the name `.plan-policy-check:<decision>:<environment>:<provider>:<region>` that can be extended in your pipeline.

### `plan-policy-check` Component Inputs

| Name            | Type      | Description                                                            | Required | Default  |
| --------------- | --------- | ---------------------------------------------------------------------- | -------- | -------- |
| `decision`      | `string`  | The OPA decision to evaluate (e.g., 'terraform')                       | yes      |          |
| `environment`   | `string`  | The environment (e.g., test, prod)                                     | yes      |          |
| `provider`      | `string`  | The provider (e.g., multi, aws, azure)                                 | yes      |          |
| `region`        | `string`  | The region (e.g., global, us-east-1)                                   | yes      |          |
| `allow-failure` | `boolean` | Whether the job should be allowed to fail without failing the pipeline | no       | `false`  |
| `opa-version`   | `string`  | The version of OPA to use                                              | no       | `v1.4.2` |

### `stack-plan-and-apply` Component

The `stack-plan-and-apply` component is designed for stack-based deployments. It creates hidden jobs based on the inputs provided:

- `.plan:<environment>:<provider>:<region>:<stack>`: Navigates to `environments/<environment>/<provider>/<region>/<stack>`
- `.apply:<environment>:<provider>:<region>:<stack>`: Applies changes in the stack directory

All jobs run `terraform init`, create plan files (`plan.tfplan`, `plan.json`, `plan.report.json`), and handle apply logic based on the `use-plan` setting. Artifacts expire after 30 minutes by default.

### `stack-plan-and-apply` Component Inputs

| Name          | Type      | Description                                                                                | Required | Default |
| ------------- | --------- | ------------------------------------------------------------------------------------------ | -------- | ------- |
| `environment` | `string`  | `prod`, `test`, etc.                                                                       | yes      |         |
| `provider`    | `string`  | `aws`, `vault`, etc.                                                                       | yes      |         |
| `region`      | `string`  | `global`, `us-east-1`, etc.                                                                | yes      |         |
| `stack`       | `string`  | Stack name for partitioning (foundation, compute, data, etc.)                              | yes      |         |
| `use-plan`    | `boolean` | If true, the apply job expects a saved plan; if false, it applies directly with a warning. | no       | `true`  |

### `stack-plan-policy-check` Component

The `stack-plan-policy-check` component is similar to the `plan-policy-check` component but is designed for stack-based deployments. It evaluates the plan.json file in a specific stack directory against policies defined in a .opa/ directory.

The component creates a hidden job with the name `.stack-plan-policy-check:<decision>:<environment>:<provider>:<region>:<stack>` that can be extended in your pipeline.

### `stack-plan-policy-check` Component Inputs

| Name            | Type      | Description                                                            | Required | Default  |
| --------------- | --------- | ---------------------------------------------------------------------- | -------- | -------- |
| `decision`      | `string`  | The OPA decision to evaluate (e.g., 'terraform')                       | yes      |          |
| `environment`   | `string`  | The environment (e.g., test, prod)                                     | yes      |          |
| `provider`      | `string`  | The provider (e.g., multi, aws, azure)                                 | yes      |          |
| `region`        | `string`  | The region (e.g., global, us-east-1)                                   | yes      |          |
| `stack`         | `string`  | The stack name                                                         | yes      |          |
| `allow-failure` | `boolean` | Whether the job should be allowed to fail without failing the pipeline | no       | `false`  |
| `opa-version`   | `string`  | The version of OPA to use                                              | no       | `v1.4.2` |

## `format-check` Component

The `format-check` component creates a hidden `.format-check` job that runs `terraform fmt -recursive -check -diff` on a codebase, checking the formatting of the terraform code.

### `format-check` Component Inputs

| Name                      | Type     | Description                                                                                  | Required | Default  |
| ------------------------- | -------- | -------------------------------------------------------------------------------------------- | -------- | -------- |
| `terraform-image-version` | `string` | the version of `${CI_DEPENDENCY_PROXY_DIRECT_GROUP_IMAGE_PREFIX}/hashicorp/terraform` to use | no       | `latest` |

## `publish-module` Component

The `publish-module` component creates a hidden `.publish-module:<terraform-module-name>` job that publishes a terraform module to the project running the CI/CD pipeline.

### `publish-module` Component Inputs

| Name                       | Type     | Description                                                                                                | Required | Default                      |
| -------------------------- | -------- | ---------------------------------------------------------------------------------------------------------- | -------- | ---------------------------- |
| `terraform-module-dir`     | `string` | The relative path to the root directory of the Terraform project.                                          | no       | `modules/${CI_PROJECT_NAME}` |
| `terraform-module-name`    | `string` | The name of your Terraform module, must not have any spaces or underscores (will be translated to hyphens) | no       | `${CI_PROJECT_NAME}`         |
| `terraform-module-system`  | `string` | The system or provider your Terraform module targets (ex. `local`, `aws`, `google`)                        | yes      |                              |
| `terraform-module-version` | `string` | The version - it's recommended to follow SemVer for Terraform Module Versioning.                           | no       | `${CI_COMMIT_TAG}`           |
